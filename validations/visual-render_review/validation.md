# 完整方块覆盖验证

当前验证针对 49 号路线 A：保留完整原生方块面，在实体阶段之后用原生深度偏移覆盖实时投影。默认缩放与经典动画均保持检查点的时长和语义；经典动画仍保留透明度，不改成另一种动画。历史调查见[可行性报告](../../documents/research/review-projection_feasibility.md)。

## 目标

在参考端 26.3 NeoForge 的 Vulkan 客户端，对照原版完整方块、原版玻璃及黑曜石、上游内饰和检查点动画，验证六向覆盖、遮挡、无线平面、薄物体、环境光与两个出口裁切用例。

## 运行

先确认登记的固定 MCP 输入和正常 Loader 运行环境可用，从仓库根目录执行：

```powershell
.\gradlew.bat :version:26.3-neoforge:jar :version:26.3-neoforge:probeJar
python -X utf8 components/runtime_validation/render_review.py verify
```

同一入口也由 `:runtime_validation:verifyRenderReview` 调用。验证只读源世界并复制到自己的 `instance/`，不改动日常实例。每次运行创建默认和经典两个隔离副本，顺序启动；自动实例为 1920×1080、静音、四个逻辑核及低优先级。MCP 负责进入世界、原生定位与视角、切换透明设置、截图和保存退出；项目探针负责布置几何、频道及检查实际完整选中和碰撞形状。

两档“改进透明显示”均检查固定场景。默认模式另拍六向 64 格距离、正视和掠射、实体前景、玻璃及水、地毯／雪层／火把、白天／夜晚／火把旁／阴影。两种动画在北向有线面和无线平面拍摄中间帧。探针在供电切换两个游戏 tick 后调用原版 tick 冻结十秒，再恢复；不修改产品时长。阶段文件记录实际冻结窗口。

运行器写入 `result/candidate.json` 的 `CAPTURED_PENDING_REVIEW`，不自动判定视觉通过。逐张查看原图后记录“一致／有差异／无法比较”，指出薄物体与距离角度限制。候选身份只在最终交接清单登记一次；构建与其他端运行摘要由当前状态页链接。

## 通过标准

- 原生完整选择与碰撞形状成立，不引入显示方块实体，不隐藏原生方块面。
- 六向投影覆盖稳定，实体前景仍遮挡，透明前景正常合成，无线区域内部不被节点方块盖住。
- 两种动画的中间帧与检查点语义一致；紧贴出口和间隔一纹素的面均保留，无明显边缘条带。
- 方块与内饰按实际光照变化；普通玻璃和黑曜石作为相邻对照，发现差异即修复或明确记录。
- 正常保存退出，输入释放，端点移除；截图和日志不能代替用户的独立视觉验收。
