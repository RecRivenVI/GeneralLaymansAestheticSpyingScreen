# 路线 B 实现与交付核对

调查日期：2026-10-20。路线 B 已在 1.21.1 NeoForge 打通有界订阅、独立世界、远端、下界、Sable 三种摆放与 Sodium。联合矩阵、相关修正的定向复验和发行构件冒烟已有实机证据；验收实例已准备、不启动。用户视觉验收仍独立进行；本轮没有两个真实客户端并发和粒子压力性能的结论，Iris 不在范围内。

## 问题

需要在保留完整方块、原生覆盖层及两种旧动画的条件下，使源位于玩家加载范围外、其他维度或 Sable 子世界时仍能显示。主要风险为原生回调误用玩家世界、子世界姿态与裁切平面不一致，以及源区块收到数据后没有真正推进实体或绘制网格。

## 方法

标准答案使用路线 A 的 1.21.1 发行构件，固定光照、玩家相机与场景；比较地形、透明物、箱盖、告示牌、实体装备、运动、粒子和源相机水雾。独立视图另测 8192 格远端与下界。Sable 分为终端、投影方块、两端三个摆放，分别检查平移、三轴旋转、旋转中心、非均匀缩放以及穿过出口面的棋盘管道。

Sodium 使用依赖说明中登记的稳定版，与 Sable 联合运行。Fancy 和 Fabulous 的实际值由游戏内探针记录。MCP 负责进入世界、原生命令、移动视角、界面、截图和保存退出；项目探针负责固定场景与项目内部状态。自定义命令不借助 MCP 未支持的命令分类绕过执行。

最终验证入口见[验证说明](../../validations/integration-remote_projection/validation.md)。结果根目录为 `validations/integration-remote_projection/result`；候选身份只登记在该目录的 `candidate.json`。

## 发现

### 与路线 A 的比较

| 项目 | 结论与可见影响 |
| --- | --- |
| 近端地形、白天与夜间光照、火把、透明前景 | 一致：固定视角下的形状、遮挡和亮度相符 |
| 箱盖、告示牌、装备与 glowing 复位 | 一致：改为增量更新后，箱盖在跨越周期刷新的九秒样本中持续开启，文字与装备更新相符 |
| 源相机水雾 | 一致：使用源世界的相机流体状态 |
| 下界光照与主世界恢复 | 一致：源使用自己的光照贴图，直接进入下界的主要色块与投影通道差值不超过 2/255；恢复绑定后玩家世界亮度不再被源捕获改变 |
| Sodium 粒子 | 一致：近端、远端和下界均恢复显示；源视图采用原版提交，保留 Sodium 地形路径，内部快速提交失效点尚未定位 |
| 云与随机粒子 | 有差异：独立世界的随机相位和采样时刻不同，未追求逐像素一致 |
| 有界源视野 | 有差异：预算外显示空背景，Sable 图块占用同一订阅名额；路线 A 可以使用玩家已加载的更大范围 |
| 首次观看与源跨区块移动 | 有差异：首次快照和网格编译需要等待，源范围更换时保留上一帧，数据到齐后继续原动画 |
| 无对照场景中的新任意姿态 | 无法比较：旧实现不支持此路径；按完整仿射公式、解析测试及穿面实景核对 |

近端原图为 `D:\Workspaces\Scratches\GlassProduction\route-b\rich-standard-fixed\result`；无 Sable 的路线 B 为 `rich-facade-candidate-fixed\result`，Sable 与 Sodium 的箱盖和运动复核为 `rich-light-sodium-fixed\result`。前两次可选模组类加载失败，以及错误遮挡夹具的截图均保留为失败材料，不计入一致结论。

### 强加载与生命周期

每个源使用 GLASS 自有 owner 和引用计数。原生 FakePlayer 与一个真实客户端的服务端订阅验证了两引用共用一个 owner、释放一个保留一个、最后释放归零；这不是两个真实客户端的网络并发测试。没有调用 `setChunkForced`，原版强加载集合保持不变。

Sable 与 Sodium 联合样本已验证跨区块平移、8192 格移动、原生卸载、重新订阅恢复、退出重启恢复和资源重载。相应材料在 `sable-terminal-sodium-moving`、`sable-terminal-sodium-lifecycle-native` 及其 `restart` 结果目录。早期保存指针错误导致的恢复失败单独保留，未冒充成功。

默认 25 个传输区块需要原生半径四的 FULL 邻域，实际为 81 个普通区块；一个或两个 Sable 图块分别为 82、83 个加载位置。原先仅中心实体推进的问题已修正，最终矩阵特意在相邻源区块安排移动、缩放和死亡实体。配置的唯一说明见[服务端预算](../usage/configuration-remote_projection.md)。建议试验阶段保留当前保守默认值，全服并发容量由用户决定。

### 联合矩阵与发行构件

原版分派与 Sodium 分派各四个场景：无子世界、终端船、投影方块船和双船。每个子世界场景保留轴向穿面、倾斜缩放穿面、三个运动时刻、复位和两处 GUI 截图；无子世界场景保留无线、根节点在视锥外、远端与下界更新、权限拒绝和恢复，以及最终释放记录。

八场景联合矩阵完成后，按影响范围补验了粒子精确重载、源光照贴图、主世界绑定恢复和 Sodium 原版粒子提交；没有因产物指纹变化重跑无关几何场景。`final-lighting-vanilla`、`final-lighting-sodium` 含原生下界直接观察对照，`final-state-restore` 含主世界亮度恢复，`particle-source-fixed` 为保留全局 Sodium 默认配置的最终粒子样本。首次钩子重载不匹配的启动失败保留在 `particle-source-submission`，不计成功，也不是 MCP 缺陷。

无线补验发现三处不同问题：早期工具在切换终端后误读旧终端的就绪状态，9/25 区块截图不作画面结论；工具现等待同一终端连续就绪。数据完整后，Sodium 网格仍画出了捕获规则应排除的终端，已在 `LevelSlice` 补齐同一规则。内饰实体层提交又关闭了地形仍需使用的光照贴图，现恢复当前世界绑定。最终 `wireless-light-sodium` 与 `wireless-final-vanilla` 的三角内容、根节点视锥外画面、地板和内饰光照相符。

有差异：Sodium 主世界普通色墙有更暗的渐变，投影内容没有出现相同程度的差异；这一项不能归因于随机相位。使用同一世界副本启动 A 与 Sodium 作对照时，旧 A 的 `LevelExtractorMixin` 与 Sodium 合并的 `setupRender` 钩子冲突，进入世界前即失败，材料保留在 `physical-control-a-sodium`。因此无法确定该主世界差异由 B 引入还是现有渲染组合产生，作为开放项，不宣称整帧一致。

五端最终 `check` 与 `verifyRelease` 成功，严格合规为零失败、零警告。发行 JAR 使用单独的完整 Loader 实例与七个顶层 JAR 组合运行，实际操作 F8 暂停、恢复和保存退出。演示只使用探针，不进入产品构件。验收入口与三世界短清单见[体验清单](../development/testing-remote_acceptance.md)。

`packaged-final` 在 Sodium 可见性修正后再次使用七个原样发行 JAR 完成进入世界、F8 暂停与恢复、保存退出，退出码为零。随后内饰光照修正仅补验受影响的无线与有线返回场景。倾斜石框和棋盘管道原图已人工查看；用户验收目录没有启动，也没有复用为自动测试目录。

候选、证据与 MCP 能力清单分别记录在结果根目录的 `candidate.json`、`visual-review.json` 和 `mcp-limitations.json`。仅保留固定证据、必要失败材料与当前交付；旧可重建原型实例和两套旧安装缓存已送回收站，保护的迁移材料和路线 A 验收实例未动。

## 结论

实现与加载器差异见[架构说明](../design/architecture-remote_projection.md)和[移植说明](../development/porting-remote_projection.md)。范围限于已登记的 Sable、Sodium 发行和固定场景，不提供 Iris 适配。路线 A 已签名提交并推送；路线 B 工作树不提交、不推送，验收实例只准备、不启动。
