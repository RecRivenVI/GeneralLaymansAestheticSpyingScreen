# 完整方块覆盖的版本差异

五端均保留原生完整方块面，以正常深度测试和原生渲染层偏移覆盖投影。默认缩放、经典白色动画的算法和时长保持检查点 `671755d`；出口裁切采用固定边界余量。产品不使用显示方块实体。

## 绘制阶段

| Target | 主世界覆盖入口 | 原生深度状态 |
| --- | --- | --- |
| 26.3 NeoForge / Fabric | 主世界 `executeSolid` 的 pass 结束前 | reverse-Z，`GREATER_EQUAL`，正偏移 |
| 26.1.2 NeoForge | `AfterOpaqueFeatures` | `LESS_EQUAL`，负偏移 |
| 1.21.1 NeoForge / 1.20.1 Forge | `AFTER_CUTOUT_BLOCKS` | `LEQUAL_DEPTH_TEST` 与 `POLYGON_OFFSET_LAYERING` |

26.3 在开启世界 pass 前上传投影网格，再使用该 pass 的深度附件。26.1.2 的事件中原生全局视图栈已经包含旋转，投影顶点又已包含视图旋转，因此覆盖的动态矩阵用单位矩阵；1.x 对应事件发生在原生视图栈压入之前，不沿用这一处理。深度写入保持开启，前景实体和透明方块仍参与正常遮挡。

## 原生动态模型

信标使用原版方块模型，终端标记使用玻璃模型，水晶使用原版 End Crystal 模型的内部部件；每次提交使用方块位置的实际方块光与天空光。客户端记录已加载区块里的 GLASS 位置，区块卸载时移除，不扫描整个世界。不引入方块实体，因此完整方块仍保留原生推动行为。

26.x 使用原版的模型提交入口；1.x 使用方块模型派发器和姿态栈。Fabric 自行取得模型解析器，NeoForge 使用加载器提供的入口。捕获世界仍按上游规则省略终端，主世界的终端面完整保留。

## 区块与渲染器生命周期

NeoForge 的模型区域缓存使用带 ModelData 的构造器，捕获身份必须记录在真正执行的构造器中，后台编译再读取快照身份。1.21.1 的 RenderChunk 类型不是公开类型，构造器回调只接收 CallbackInfo。

1.21.1 每个原生区块编译派发器假定独占缓冲池；多个 GLASS 渲染器共用主世界池会使队列饥饿，并在 Fabulous 下并发取空。频道派发器独立持有一个异步编译缓冲及同步缓冲，关闭时在其邮箱中释放空闲缓冲，完成中的任务归还时释放，避免污染主世界。26.1.2 则把每个频道的原生编译任务串行化，独占一个编译缓冲；该版本取空只重新入队、不再调度，不能共用主世界池。关闭与任务共用锁，等待归还后释放。1.20.1 自带每个派发器独立的空闲队列，无需照搬该补丁。

NeoForge 区块重新发送和 Forge 区块观看事件、Fabric 的原生 PlayerChunkSender 返回事件，均通知服务器重新计算已有投影拓扑。否则在区块仍驻留但观看者离开后返回时，不触发区块加载事件，会遗漏订阅。

26.1.2 的原生天空资源在资源重载入口创建，独立 LevelRenderer 构造后需执行该入口。测试直接在尚未就绪的区块中铺设色墙，曾导致源墙本身光照未完成；通过 MCP 在已就绪区块重建后，与原生源墙一致。这是夹具问题，不向产品添加补光。

## 验证范围

参考端的六向、透明设置、动画与裁切对照见[覆盖验证](../../validations/visual-render_review/validation.md)，当前结果和证据位置见[状态页](../project/status-render_review.md)。发行安装与开发 classpath 分开验证；探针是单独的验证模组，不进入发行 JAR。Forge 探针使用官方 ModDevGradle 的原生命名到 SRG 重映射任务。

1.20.1 的原生相机以 +Z 为前向，而现代版本与投影数学以 -Z 为前向；捕获入口与相机回写分别转换半圈，避免捕获相反方向。首个世界帧的 FOV 尚未初始化时可能产生非有限投影矩阵，跳过该帧的捕获，避免原生视锥调整循环卡住。动态内饰刷新实体缓冲后显式恢复地形光照层，因为该版本跨地形层保留光照绑定。
